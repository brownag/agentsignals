# 1.1.1 -- Snapshot reports every skipped scratchpad file
## Goal
Make `snapshot_scratchpad` return `(copied, skipped)` where `skipped` lists every non-silent skipped file with path, size and reason.

## TODO items
- [ ] Check `typing` imports in miner.py; add `Tuple`, `Dict`, `Any` only if missing.
- [ ] Change the signature to `-> Tuple[List[str], List[Dict[str, Any]]]` and update the docstring.
- [ ] Add `skipped: List[Dict[str, Any]] = []`. The early return for a missing or non-dir source returns `(copied_files, skipped)`.
- [ ] Reorder the loop body so the excluded-dir check comes first and stays silent. Compute `rel_path` and check `parts` before `stat`. The spec orders the checks this way, and the old code ran stat and size first.
- [ ] `stat` failure appends `{"path": rel.as_posix(), "size_bytes": None, "reason": "unreadable"}`. Size over the cap appends `oversized` with the size. A NUL in the first 1024 bytes appends `binary` with the size. An `OSError` from `open`, `mkdir` or `copy2` appends `unreadable`, with the size if already known, else None.

It also has a `venv/` file that is silent. Assert the reason for each skipped entry, that none is in `copied`, and that nothing is copied to dest for them.

## Notes
- Current body is at miner.py:281-325. It runs stat, then the size check, then the exclusion check, then the binary check. All of them `continue` silently, so the order must change for the excluded-dir case to stay silent.
- One caller only (miner.py:415). Tests call it at tests/test_miner.py:112.
- The unreadable test must patch only one file's copy. `monkeypatch` of `miner_module.shutil.copy2` with a wrapper that raises for the target name and delegates otherwise is the safest option, and it needs `copy2` imported into the test namespace safely.
- Constraints honored: no change to MAX_SCRATCHPAD_FILE_BYTES, the excluded list, symlink handling, SessionDossier, or planning/ (apart from this todo file).
- Risk: the mkdir for the target parent runs before copy2, so a skipped-unreadable file can leave an empty dest dir. This is harmless and matches existing behavior.
